## 1. 项目解决什么问题

项目名称是 **Anime Preference Understanding & Structured Recommendation Tool Calling**：理解用户的动漫偏好，将其表达为结构化查询，供后续推荐工具使用。

当前已经实现的是基础数据和结构化目标的构建。仓库还没有一个能接收自然语言、调用训练好的模型并推荐作品的完整应用。理解这一点，可以避免看到 `training`、`inference` 等目录后，以为这些功能已经存在。

当前已实现三条彼此独立的基础流程：

```text
流程 A：作品数据
AniList API
  → fetch_anime_page()：获得一页原始 Media
  → AnimeMetadata.from_api()：逐条检查字段
  → write_jsonl()：保存原始 Media
  → write_manifest()：保存本次运行摘要

流程 B：数据集目标
人工明确指定的 SemanticSpec + 已加载的 DomainRules
  → build_query()：校验、展开规则、构建 Gold 字典
  → dumps_query()：检查完整结构并生成固定格式 JSON 文本
  → build_constraint_signature()：提取硬约束结构标签
  → build_dataset_record()：从 spec/rules 与生成元数据统一构建样本记录
  → validate_dataset_record()：重算派生字段并检查一致性

流程 C：词表治理
AniList taxonomy API
  → fetch_anilist_taxonomy()：保留完整来源响应
  → write_taxonomy_snapshot_bundle()：写 source/canonical/manifest
  → 人工 tag audit：显式批准或拒绝
  → build_executable_tag_subset()：生成批准子集并验证 DomainRules 目标
```

实际 build_dataset_record 内部会自行调用 build_query/signature，调用者无需先计算这些派生字段。

流程 B 并不直接调用流程 A。当前的规则文件是单独维护的配置，builder 也不读取采集的作品文件。

### 1.1 四个容易混淆的对象

| 对象 | 表达的事实 | 例子 |
|---|---|---|
| `AnimeMetadata` | 一部作品实际具有的属性 | 年份为 1998、集数为 26 |
| `SemanticSpec` | 要构造的数据样本明确要求哪些偏好 | 至少 2010 年、至多 24 集 |
| Gold Query | 模型未来应输出的结构化答案 | `year.min=2010`、`episodes.max=24` |
| DatasetRecordSpec | 语义来源、Gold、文本与生成溯源的外层记录 | sample_id、template_id、constraint_count |

不能因为用户提到了某作品，就把该作品的所有 genre、tag 自动写进偏好。当前 builder 只处理已输入的 spec，没有这类推断。

### 1.2 当前没有实现的环节

没有随机语义采样器、自然语言模板生成器、LLM 改写、数据集切分、训练、推荐执行器或完整的 tool-call 封装。当前 Gold 是查询参数对象，还不是带工具名和工具调用 ID 的完整 API 消息。

## 3. 理解代码需要的 Python 概念

### 3.1 类型标注不等于运行时校验

`episodes: int | None` 表达设计意图，但调用者仍能在运行时传入字符串。`dataclass` 也不会自动阻止这种赋值。因此 `from_api()`、`build_query()` 需要显式检查。

`Any` 表示静态类型检查暂时不限制值，不代表该值已经安全。`Mapping[str, Any]` 用于标注；运行时应写 `isinstance(value, Mapping)`，不能写 `isinstance(value, Mapping[str, Any])`。

### 3.2 为什么单独排除 bool

Python 中 `bool` 是 `int` 的子类：`isinstance(True, int)` 为真。但“最多 True 集”没有本项目需要的数值语义。因此代码采用：

```python
if not isinstance(value, int) or isinstance(value, bool):
    raise ValueError(...)
```

### 3.3 None、空集合和零不同

`None` 在范围规格中表示“未表达该边界”；`0` 是实际数值。空列表表示对应 operator 没有值。序列化时 Python `None` 变成 JSON `null`。

### 3.4 tuple、list、frozenset 与 MappingProxyType

输入规格使用 tuple，例如 `("Mystery",)`；最后的逗号使它成为单元素 tuple。Gold 使用 list，因为 JSON 中相应结构是数组。规则 allowlist 使用 frozenset，便于检查成员且不能增删。`MappingProxyType` 提供字典的只读视图。

`frozen=True` 只阻止 dataclass 字段重新赋值，不会递归冻结其中的 list。`AnimeMetadata.genres` 和 `.tags` 仍是 list；`DomainRules.tag_groups` 则由加载器封装为只读映射。不要把所有 frozen dataclass 都称为“深度不可变”。

### 3.5 闭包与内部辅助函数

`build_query()` 内部定义的函数仅供这次构建使用。例如 `validate_set_constraint()` 可以访问外层 `operators`。这减少参数传递，但阅读时要同时看外层变量。辅助函数并不是另一个对外 API。

### 3.6 异常链和资源释放

`raise RuntimeError(...) from exc` 增加业务上下文并保留原因。`with path.open(...)` 或 `with urlopen(...)` 保证正常结束和异常退出时关闭资源；它不保证整个操作具有事务性，也不会自动删除已写入的半成品。

## 4. 单页 AniList 请求

源码：[anilist_client.py](../src/anime_pref/data/anilist_client.py)

### 4.1 ANIME_PAGE_QUERY 常量

这是 GraphQL 查询文本，不是一个函数。它声明 `$page` 和 `$perPage` 两个变量，请求 `Page.pageInfo.currentPage/hasNextPage`，以及 `media(type: ANIME, sort: ID)`。

作品字段包括 `id`、三种标题、`format`、`status`、`episodes`、`seasonYear`、`genres`、`tags{name rank}`。`sort: ID` 明确了排序，但并不等于远端数据库在多次请求之间被冻结。

GraphQL 与 SQL 不同，这段代码发送的是服务器支持的字段选择。当前客户端只接收结果，没有在本地执行查询语言。

### 4.2 fetch_anime_page()

```python
fetch_anime_page(
    page: int,
    per_page: int,
    *,
    endpoint: str = "https://graphql.anilist.co",
    timeout_seconds: float = 30,
) -> dict[str, Any]
```

`*` 后参数必须使用名称传入。函数返回 `response["data"]["Page"]`，不是完整 HTTP 响应，也不是只返回作品列表。

| 阶段 | 当前操作 | 为什么需要 |
|---|---|---|
| 参数检查 | page 是正整数；per_page 是 1–50 的整数；排除 bool | 提前拒绝明显无效请求 |
| 超时检查 | `timeout_seconds <= 0` 时拒绝 | 防止非正超时 |
| 构建 payload | query 文本 + variables 字典 | 让分页值与查询正文分开 |
| 编码 | `json.dumps(payload).encode("utf-8")` | urllib 请求正文需要字节 |
| 请求 | JSON Content-Type、POST、urlopen timeout | 发送至指定 endpoint |
| 解析 | 读取 bytes，UTF-8 解码，再 json.loads | 得到 Python 对象 |
| GraphQL 检查 | 顶层存在非空 errors 则失败 | HTTP 200 不代表 GraphQL 执行成功 |
| 结构检查 | data/Page 是 dict；media 是 list；hasNextPage 是 bool | 为分页调用方提供基本结构保证 |
| 返回 | page_data | 单条 Media 内容留给下一层检查 |

输入 `fetch_anime_page(1, 2)` 成功时，返回形状如下；这里是示意结构，不是本次实时 API 输出：

```python
{
    "pageInfo": {"currentPage": 1, "hasNextPage": True},
    "media": [{"id": 1, ...}, {"id": 5, ...}],
}
```

异常处理按顺序捕获 `HTTPError`、`URLError`，转换成 `RuntimeError`；已构造的 RuntimeError 直接重新抛出；其他请求阶段异常进入最后的宽泛捕获。

边界：客户端尚未逐项验证 Media，也未验证 currentPage 的类型与请求页一致。JSON 顶层未先检查 dict，非预期顶层值可能进入宽泛异常包装。直接调用客户端时，超时的类型/有限性检查不如 CLI 严格。Request 对象在 try 之前构建，因此不能把所有 endpoint 参数错误都概括成已包装的网络错误。当前没有重试、429 退避或断点续采。

## 5. 作品元数据校验

源码：[anime_metadata.py](../src/anime_pref/schemas/anime_metadata.py)

### 5.1 AnimeTag 与 AnimeMetadata

`AnimeTag` 保存名称和 rank。`AnimeMetadata` 保存一条作品的标准化视图。

| 原始 API 字段 | dataclass 字段 | 当前接受的值 |
|---|---|---|
| id | id | int，排除 bool；必需 |
| title.romaji | title_romaji | str 或 None |
| title.english | title_english | str 或 None |
| title.native | title_native | str 或 None |
| format | format | str 或 None |
| status | status | str 或 None |
| episodes | episodes | int 或 None，排除 bool |
| seasonYear | season_year | int 或 None，排除 bool |
| genres | genres | 必需的字符串 list，允许空 list |
| tags | tags | 必需的 list，元素转换成 AnimeTag |

### 5.2 AnimeMetadata.from_api()

这是 `@classmethod`，第一个隐式参数是类 `cls`。最后用 `cls(...)` 构造实例，调用方式是 `AnimeMetadata.from_api(media)`。

执行过程：

1. 检查 media 为 dict，避免对 list 调用 `.get()` 泄漏 AttributeError。
2. 取 id；缺失/None 或非整数时报 ValueError。
3. 取 title；允许缺失或 None；若是 dict，逐项检查三种名称。
4. 检查 format/status 的字符串类型，episodes/seasonYear 的数值类型。
5. 检查 genres 容器及每个元素。
6. 遍历 tags，使用 enumerate 得到索引，用于错误消息定位。
7. 检查每个 tag 是 dict，name/rank 必需，rank 为 0–100 整数且不是 bool。
8. 构造 AnimeTag 列表，最终返回 AnimeMetadata。

示例：

```python
media = {
    "id": 100,
    "title": {"romaji": "Example", "english": None, "native": "示例"},
    "format": "TV", "status": "FINISHED",
    "episodes": None, "seasonYear": 2020,
    "genres": ["Drama"],
    "tags": [{"name": "Time Loop", "rank": 80}],
}
metadata = AnimeMetadata.from_api(media)
# metadata.season_year == 2020
# metadata.episodes is None
# metadata.tags[0].name == "Time Loop"
```

读取缺失可空字段时 `.get()` 返回 None，因此“字段不存在”和“明确 null”在当前模型中被合并。函数不检查真实 taxonomy，不拒绝未知 format 字符串，也不限制 episodes/year 的业务范围。它不丢弃无效记录，而是整条失败。

当前标题赋值放在验证循环内部，会重复三次赋值，但不改变最终结果。genres 直接复用了输入 list；它不是输入数据的完整深拷贝。理解这些细节比把 dataclass 误认为自动清洗器更重要。

## 6. JSONL 与 manifest 写入

源码：[io.py](../src/anime_pref/data/io.py)

### 6.1 write_jsonl(records, path) → int

`records` 标注为 Iterable，可以是 list，也可以是生成器/迭代器。函数不使用 `len(records)`，而是在每条写入后递增 count，因此支持逐项消费输入。

核心逻辑：

```python
path.parent.mkdir(parents=True, exist_ok=True)
count = 0
with path.open("x", encoding="utf-8") as f:
    for record in records:
        line = json.dumps(record, ensure_ascii=False) + "\n"
        f.write(line)
        count += 1
return count
```

`parents=True` 创建中间目录；`exist_ok=True` 允许目录已存在。`x` 是独占创建模式，文件存在时抛 FileExistsError，避免覆盖原始缓存。

JSONL 是每行一个独立 JSON 对象，不是外层包一个数组。若字符串内部含换行，JSON 编码会转义该换行，因此仍可按物理行读取记录。空输入生成零字节文件并返回 0。

中文通过 `ensure_ascii=False` 保留为 Unicode 字符，再由文件编码写成 UTF-8。Windows 文本模式可能将行结束写成 CRLF；`splitlines()` 能正常读取，不能把 `"\n"` 拼接误认为严格保证 Unix LF 字节。

函数不执行 schema validation，也没有 `allow_nan=False`；它假设上游提供合适的数据。生成器异常、编码失败、磁盘错误都会向上传播。如果第二条失败，第一条和已有文件可能保留；没有返回 count 并不意味着没有产生文件。

### 6.2 write_manifest(manifest, path) → None

同样创建父目录和使用 `x` 模式。区别是写一个 JSON 对象，使用 `json.dump(..., indent=2)` 直接写到文件，并追加换行。

manifest 是运行摘要。该函数不检查摘要的字段或统计是否正确：统计由 main 负责，I/O 层只保存。已有文件拒绝覆盖；序列化或写入中途出错仍可能留下不完整 manifest。当前实现不是“临时文件写完再原子重命名”。

## 7. 采集脚本与命令行

源码：[fetch_anilist.py](../scripts/fetch_anilist.py)

### 7.1 模块初始化和 positive_int()

`Path(__file__).resolve().parents[1]` 从脚本所在位置定位项目根目录。把根目录下的 src 插入 `sys.path` 后，即使未安装包，也可直接执行脚本并导入 anime_pref。

`positive_int(value: str) -> int` 是 argparse 的转换函数。先 `int(value)`，再检查至少为 1。输入 `"2"` 返回 2；`"0"` 抛 ArgumentTypeError；`"abc"` 在 int 转换时抛 ValueError，argparse 会把这种转换失败作为命令行参数错误报告。

### 7.2 main() → int：配置阶段

| 参数 | 作用 | 默认或约束 |
|---|---|---|
| --config | JSON 配置路径 | 项目根目录/configs/data.json |
| --pages | 最多获取页数 | 覆盖配置 pages |
| --per-page | 请求每页条数 | 覆盖配置；1–50 |
| --output | 缓存目录 | 覆盖配置 output |
| --dry-run | 输出解析后的配置 | 不进入采集循环 |

解析顺序是“读取配置 → 非 None 的命令行值覆盖 → 验证 → 解析输出路径”。默认配置为 pages=1、per_page=10、timeout_seconds=30、output=`data/raw/anilist`，endpoint 为 AniList GraphQL 地址。

相对 output 基于项目根目录；相对自定义 config 基于进程当前工作目录。二者不是同一条路径规则。

配置验证检查 pages/per_page 的精确 int 类型、timeout 为正的有限 int/float、endpoint 为以 `https://` 开头的字符串。不会严格拒绝配置中的额外键，也不把 HTTPS 前缀检查当成完整 URL 验证。

### 7.3 main()：采集循环

初始 `page=1`，`total_pages_fetched=0`，`total_records=0`，`file_list=[]`。

每轮先检查 page 是否超过 max_pages，再请求当前页。所有 Media 通过 from_api 后，才把这一页的原始 media_list 写入文件。注意：校验生成的 dataclass 没有保存下来，JSONL 保留 API 字段 `seasonYear`，不会变成 `season_year`。

`filename = f"page_{page:04d}.jsonl"` 中 `04d` 表示十进制数至少四位、不足补零。第一页是 page_0001.jsonl。

写入成功后，使用 write_jsonl 的返回值累计实际记录数，实际页数加一，文件路径加入列表。如果 hasNextPage 为 False，立即退出；否则 sleep(1)，page 加一进入下一轮。即使已写完配置要求的最后一页，如果 hasNextPage 为 True，也会多等待一次才在循环顶部退出。

main 使用 `.get('media', [])` 等默认值；依赖客户端此前已检查对应字段。默认值不是独立验证，若未来换了未验证的客户端，这里可能把缺失数据误当成空页。

### 7.4 main()：manifest 与退出

| 字段 | 当前含义 |
|---|---|
| fetch_time | 写 manifest 前的 UTC 时间，ISO 8601 含 +00:00 |
| endpoint | 实际使用的 endpoint |
| requested_pages | 本次配置的页数上限，不是实际请求次数 |
| actual_pages | 已成功保存的页数 |
| per_page | 请求页容量，不保证每页实际返回相同条数 |
| total_records | 已成功写入记录总数 |
| files | 当前保存完整路径字符串 |
| schema_version | 固定字符串 0.1；不是自动读取领域规则版本 |

成功返回 0；捕获 NotImplementedError 返回 2；捕获列出的 I/O、配置、校验和运行异常返回 1。`raise SystemExit(main())` 将返回值传给操作系统。argparse 在 main 的 try 之外执行，所以 `--help` 或无效 CLI 参数可能直接触发 SystemExit，而不走后面的 except。

若第二页校验失败，第一页可能已存在，而本次不会进入最终 manifest 写入。旧目录中原先已有的 manifest 不会自动消失，写 manifest 本身失败也可能留下部分文件。因此“失败不生成成功摘要”仅描述正常控制流，不能推导出目录一定干净。当前建议每次采集选择新目录。

## 8. Semantic specification 数据模型

源码：[preference_query.py](../src/anime_pref/schemas/preference_query.py)

### 8.1 SetConstraintSpec

三个 tuple：all_of、any_of、none_of，默认都为空。

- all_of：同时要求列表内所有标签。
- any_of：要求列表内至少一个标签。
- none_of：排除列表内所有标签。

这是查询字段设计的解释；实际检索执行器尚未实现。不要用当前 builder 成功返回来证明数据库中一定存在满足查询的作品。

### 8.2 RangeConstraintSpec

min/max 为 `int | None`，文档约定包含边界。例如 min=12、max=24 表达闭区间。模型本身不校验，检查发生在 builder。

### 8.3 SemanticSpec

| 字段 | 输入类型 | 结果去向 |
|---|---|---|
| genres、tags | SetConstraintSpec | hard_constraints 同名字段 |
| tag_groups | SetConstraintSpec | 展开到 tags；自身不输出 |
| year、episodes | RangeConstraintSpec | hard_constraints 的范围对象 |
| formats、status | tuple[str, ...] | 排序后的 JSON 数组 |
| reference_titles | tuple[str, ...] | 顶层数组；保持字符串和顺序 |
| soft_preferences | tuple[str, ...] | 同上 |
| unresolved_preferences | tuple[str, ...] | 同上 |

`field(default_factory=SetConstraintSpec)` 为每个新 spec 创建自己的默认对象。没有输入的偏好保持空值，不会从参考作品补充 genre/tag。soft 与 unresolved 的归类已在输入里决定，builder 不负责判断一句话应该放在哪一个字段。v0.1.1 的 soft_preferences 必须属于批准词表，目前该词表为空；未知表达可由上游明确放入 unresolved_preferences，但 builder 不会自动搬移。formats/status 为可接受值的 OR 列表。

## 9. 领域规则加载

源码：[query_builder.py](../src/anime_pref/data/query_builder.py)，配置：[domain_rules.v0.1.1.json](../configs/domain_rules.v0.1.1.json)。

### 9.1 三个规则模型

| 模型 | 字段与含义 |
|---|---|
| TagGroupRule | tags 为展开目标 tuple；allowed_operators 为许可 operator 集合；normalization_rule_id 为来源标识 |
| NumericRule | minimum/maximum 是可选的有效性边界，None 表示该方向没有配置限制 |
| DomainRules | schema_version、四类 taxonomy 白名单、tag_groups、soft_preferences，以及 episodes/year 数值规则 |

当前配置：19 个 genres，3 个 Harem tags，7 个 formats，5 个 statuses；soft_preferences 为空。
HAREM 允许 any_of/none_of，不允许 all_of；规则 ID 为 HAREM_EXPANSION_V0_1_1。
year 范围为 1900–2100，episodes 最小为 1、最大未设置。
这些是当前本地配置的事实，不表示已经完成全量 taxonomy 的获取与审核。

### 9.2 load_domain_rules(path)

输入 Path，输出 DomainRules。函数首先用 UTF-8 读取 JSON，文件、编码、JSON 解析错误通过异常链包装为 ValueError。后续契约检查同样抛 ValueError。

执行顺序：

1. 顶层必须是 dict，键集合精确等于 schema_version/taxonomy/tag_groups/numeric_rules。
2. schema_version 必须是非空字符串。当前实现没有限定只能为 0.1.1，也没有在此拒绝版本字符串首尾空白；不要把文件名当成运行时版本校验。
3. taxonomy 的键集合也必须精确匹配，防止拼错字段被静默忽略。
4. 内部 validate_allowlist 检查 list、非空字符串；先 strip，再检查规范化后的重复。soft 允许空列表，其他四个白名单要求非空。
5. 逐个读取标签组。组名会 strip；组成员也清理后查重，并要求属于 taxonomy.tags。
6. allowed_operators 只能由 all_of/any_of/none_of 组成，非空且不重复。
7. normalization_rule_id 必须非空、无首尾空白，并且在整个配置内唯一。
8. numeric_rules 精确包含 year/episodes；各项精确包含 minimum/maximum。值必须 int 或 None，排除 bool；有两个值时 minimum 不大于 maximum。
9. 转换为 tuple、frozenset、TagGroupRule、NumericRule 和 MappingProxyType。

为什么白名单是 frozenset：成员检查频繁，且规则不应在构建期间被意外增删。
为什么有 MappingProxyType：frozen dataclass 只防止字段重新赋值，不能自行冻结普通 dict。

**配置与输入采用不同政策**：loader 会清理某些配置字符串；build_query 对 canonical spec 拒绝首尾空白，不替用户修正输入。直接手工构造 DomainRules 可以绕开 loader 的完整配置验证，所以正式路径应从 loader 进入。

## 10. 确定性 Gold JSON 构建

### 10.1 build_query(spec, rules)

输入 SemanticSpec 和 DomainRules，输出全字段的普通 dict；不读自然语言，不读取作品缓存。
非法语义通常以 ValueError 报告。这个函数的目标是忠实转换已明确的输入，不是推荐执行或 satisfiability 求解。

四个内部步骤值得逐段阅读：

**validate_string_tuple(value, name, allowlist, sort_output)**

要求 tuple；每项为非空、无首尾空白的 str；不得重复。若给 allowlist，逐项精确命中。
转换为 list 后，根据 sort_output 决定排序。genres/tags/formats/status 排序，三个文本字段保留顺序。
即使 reference 不查词表，也不允许重复或首尾空白。

**validate_set_constraint(value, name, allowlist)**

要求 SetConstraintSpec，对三个 operator 调用前一函数。
随后检查 all/any、all/none、any/none 的交集，任意重叠即拒绝。
这是项目当前输入政策；有些重叠可能仅冗余，不能统称所有重叠都在逻辑上矛盾。

**标签组展开**

先校验直接 tags 与 tag_groups，再逐 operator 构建 combined：
复制直接 tags → 检查组允许该 operator → 添加 group.tags → 检查重复 → 排序。
之后还要检查展开结果跨 operator 的交集。
故不能直接用 set 去重：那会掩盖上游重复指定或多个来源冲突。

```text
tag_groups.any_of=("HAREM",)
    → tags.any_of=["Female Harem","Male Harem","Mixed Gender Harem"]

tag_groups.none_of=("HAREM",)
    → tags.none_of=["Female Harem","Male Harem","Mixed Gender Harem"]

tag_groups.all_of=("HAREM",)
    → ValueError：配置未许可该 operator
```

限制来自 TagGroupRule.allowed_operators，而非代码里写 if group_name == "HAREM"。
tag_groups 不出现在 Gold，但保存在 DatasetRecord 的源 spec 内。

**validate_range(value, name, rule)**

要求 RangeConstraintSpec。None 直接保留；其余必须 int 且非 bool。
应用 NumericRule 的上下界，并检查用户 min <= max。
例如规则 year.minimum=1900 不会把未表达的 year.min 自动变成 1900。

最后构建 hard_constraints 和三个文本字段，依次执行 validate_query_structure 和 validate_query_domain。
domain validator 本身也调用结构校验，因此当前存在重复校验；这是实际调用关系，本次没有改变它。

### 10.2 空值与 soft 字段

空数组和 null 必须显式保留。formats/status 为 OR 列表，没有独立 NOT 结构。
soft_preferences 不是“任何模糊文本的容器”：当前白名单为空，非空 soft 输入无法通过领域校验。
unresolved_preferences 可保存没有批准映射的 canonical 表达，但调用者要自己决定分类。

## 11. 校验分层与 canonical 序列化

源码：[query_validation.py](../src/anime_pref/data/query_validation.py)、[domain_validation.py](../src/anime_pref/data/domain_validation.py)。

```text
JSON 文本
  → parser（未来模型输出管道尚未实现）
  → Python JSON 值
  → validate_query_structure：结构/Schema 语义
  → validate_query_domain(query, rules)：可执行词表/版本化边界
  → canonicalize_query：新建稳定形式
  → dumps_query：JSON 字符串
```

上图是职责顺序，不表示已有一个 parser 总入口。dumps_query 自己只调用 canonicalize_query，后者只做结构校验；不会自动调用 domain validation。

### 11.1 validate_query_structure(query)

输入 Mapping，成功返回 None，不修改对象。
内部 require_mapping_with_keys 用集合比较每层键，拒绝缺失/额外键，允许任意插入顺序。
require_string_list 要求 list，元素非空、无首尾空白、唯一；不要求已排序。

genres/tags 检查三个 operator 及交集。
year/episodes 检查 int|None、排除 bool、min/max 顺序；episodes 还要求每个非空 bound >= 1。
formats/status 检查普通字符串 list；reference/soft/unresolved 使用相同字符串结构检查。

因此结构校验并非只检查“长得像 JSON”：它还承担 operator 和范围的 Schema 语义。
但 `"Unknown Genre"` 仍可能通过结构校验，因为此层没有 DomainRules。

### 11.2 validate_query(query)

它是兼容旧代码的结构校验别名，只调用 validate_query_structure。
不要因为名称较宽泛，就误以为它同时证明领域合法。
未来统计 parse/schema/domain 指标时，应使用显式的层名。

### 11.3 validate_query_domain(query, rules)

先执行结构校验，随后在函数内部导入 DomainRules 并做 isinstance。
局部导入用于避免 query_builder 和 domain_validation 在模块导入阶段互相要求尚未定义的类；
TYPE_CHECKING 下的导入只供静态类型工具使用，不进行运行时导入。

内部 require_allowed_values 逐项检查 genres、tags、formats、status、soft 的成员资格。
require_bounds_within_rule 应用 year/episodes 的配置边界；None 跳过，不填默认值。
reference/unresolved 不做词表映射，也不解析参考作品 ID。
成功返回 None，失败抛 ValueError，不清理、排序或改写 query。

### 11.4 canonicalize_query(query)

先调用 validate_query_structure。按四组常量重建键序：

- TOP_LEVEL_KEY_ORDER：hard_constraints、reference_titles、soft_preferences、unresolved_preferences。
- HARD_CONSTRAINT_KEY_ORDER：genres、tags、year、episodes、formats、status。
- SET_OPERATOR_KEY_ORDER：all_of、any_of、none_of。
- RANGE_KEY_ORDER：min、max。

genres/tags 的各列表以及 formats/status 排序；文本列表复制并保持原顺序。
所有 dict/list 都重新构造，空值保留。因此调用者的输入不会被就地排序。
自定义 Mapping 可在这里转成普通字典，避免直接把 Mapping 交给 json.dumps 的兼容性问题。

### 11.5 dumps_query(query)

调用 canonicalize_query，再 json.dumps：
ensure_ascii=False 保留 Unicode；separators=(",", ":") 去掉结构空格；allow_nan=False 禁止非标准数值。
返回稳定单行 str，序列化错误包装为 ValueError。

字符串值内部的空格不会被删除。例如用户文本里的 `": "` 不受 separators 控制。
**旧版“键顺序不对就拒绝”的描述已经失效**：合法乱序输入现在先规范化。
dumps_query 成功只证明结构与可序列化形式，不证明 executable vocabulary 或文本/Gold 一致。

## 12. 约束结构签名

源码：[constraint_signature.py](../src/anime_pref/data/constraint_signature.py)。

build_constraint_signature(query) 先调用共享结构校验，再提取硬约束槽位是否活跃。
固定顺序为：

```text
GENRE_ALL, GENRE_ANY, GENRE_NONE,
TAG_ALL, TAG_ANY, TAG_NONE,
YEAR_MIN, YEAR_MAX, EPISODE_MIN, EPISODE_MAX,
FORMAT, STATUS
```

集合用 bool(list)，范围用 is not None。
最后按 SIGNATURE_ORDER 过滤并以 `" + "` 连接；没有硬约束返回 NO_HARD_CONSTRAINT。
三个非硬文本字段虽然不贡献 token，仍要通过整份 query 的结构校验。

signature 表达结构，不表达值、集合长度、生成家族或规则来源。
同一个 TAG_NONE 可能对应一个 tag，也可能对应 HAREM 展开的三个 tags。
它不能替代 constraint_count、sample_id 或 generation_family 切分。

## 13. DatasetRecord 数据模型与计数

源码：[dataset_record.py](../src/anime_pref/schemas/dataset_record.py)、[dataset_record_builder.py](../src/anime_pref/data/dataset_record_builder.py)。

### 13.1 DatasetRecordSpec

| 类别 | 字段 | 谁决定 |
|---|---|---|
| 源语义 | semantic_spec | 调用方明确提供 |
| 原始文本 | user_text | 调用方提供；当前没有自动对齐检验 |
| 生成来源 | dataset_version、semantic_family、generation_family、template_id、seed | 调用方提供 |
| 可选改写来源 | paraphrase_model、prompt_version | 两者同时为 None 或同时提供 |
| 契约版本 | schema_version | build_dataset_record 从 rules 读取 |
| Gold 与审计 | gold_query、constraint_signature、constraint_count、normalization_rule_ids | 内部推导 |
| 身份 | sample_id | 完整 identity payload 的 SHA-256 |

它是数据集外层记录，不能把所有字段都当成模型的目标输出。当前没有 split 字段。
dataclass 不自动执行跨字段验证，gold_query 的嵌套结构也不是深度冻结。

### 13.2 count_hard_semantic_clauses(spec)

输入展开前 SemanticSpec，返回整数。它没有 rules 参数，不保证 taxonomy 合法。

genres 的公式：

```text
len(all_of) + int(bool(any_of)) + len(none_of)
```

tags 与 tag_groups 先分别按此公式验证并计数。如果二者 any_of 都非空，再减 1：
它们在 Gold 内共同形成一个 TAG_ANY OR 子句，不应算两条独立 OR。
all_of/none_of 仍按直接项或组概念计数。HAREM.none_of 是一个概念，不按三条展开 tag 计算。

year/episodes 每个非 None 边界加 1；formats/status 每个非空 OR 列表加 1。
reference/soft/unresolved 不计数，但仍验证基本字符串结构。

内部三个函数：

- count_set_constraint：检查模型、tuple、字符串、重复、交叉 operator 冲突后计数。
- count_range_constraint：检查 RangeConstraintSpec、int 非 bool、区间顺序后计数；不应用业务上下界。
- validate_string_tuple：检查五个字符串 tuple；其中只有 formats/status 贡献数量。

例如 genre.any_of 两项、HAREM.none_of、year.min、episodes.max，共 4 条。
count 统计表达复杂度；它不证明候选作品存在，也不证明自然语言描述忠实。

### 13.3 collect_normalization_rule_ids(spec, rules)

先调用 build_query 验证完整输入。
遍历 tag_groups 三个 operator，取实际使用组的 normalization_rule_id。
若 ID 重复则报错，返回按字符串排序的 tuple；无组则为空 tuple。

这里必须读展开前 spec。直接列出三个 Harem tags 与使用 HAREM 组可能产生相同 Gold，
却有不同的规范化来源，不能从 Gold 的三个名称反推一定使用过 HAREM_EXPANSION_V0_1_1。

## 14. 确定性样本身份

### 14.1 内部辅助函数

**_validate_identifier(value, name)**：检查 str、非空、无首尾空白。用于版本、family、template 等标识。
它没有给 semantic_family/generation_family 设置已批准的枚举集合，只检查标识形状。

**_validate_user_text(value, name="user_text")**：检查 str，且 strip 后不是空串。
与标识不同，有意义文本允许首尾空白；strip 只判空，不改变保存的 raw text。

**_validate_normalization_rule_ids(rule_ids)**：要求 tuple，每项通过标识检查，唯一且已经升序。
它没有规则对象，因此不单独证明这些 ID 实际被本条语义使用。

**_semantic_spec_to_json_mapping(spec)**：先调用 count_hard_semantic_clauses 做基本结构校验，再转换为纯 JSON 类型。
内部 set_constraint_to_mapping 对三个 operator 分别排序；formats/status 排序；文本保序；
year/episodes 保留 min/max；tag_groups 也保留。输出新 dict。

### 14.2 make_sample_id(...)

所有参数都是关键字参数，避免大量来源字段位置传错。输出 `sample_` 加 64 位小写十六进制字符。

1. 校验版本、family、template 标识；seed 必须 int 且非 bool。此处不使用 seed 启动随机数生成器。
2. user_text 按 raw text 政策验证。
3. paraphrase_model 与 prompt_version 必须成对为 None 或成对提供有效标识。
4. 检查 normalization IDs，转换完整 spec，并 canonicalize Gold。
5. 将全部参数写入 identity_payload，包括 None。
6. json.dumps 使用 sort_keys=True、紧凑 separators、Unicode 和 allow_nan=False。
7. 编码为 UTF-8 bytes，计算 hashlib.sha256(...).hexdigest()，加前缀返回。

不要混淆两种排序：Gold canonicalizer 使用契约键序；身份 JSON 的 sort_keys=True 则统一排序整个 payload 的键。
语义集合输入顺序改变不会影响身份；文本顺序或原始文本内容改变会影响身份。

make_sample_id 没有 rules 参数，也不重建 spec 对应的 Gold。因此它是身份编码函数，
单独调用不能证明 spec/Gold/规则 ID 一致；完整保证来自后面的组装与验证入口。
sample_id 包含文本、模板和版本，不能把“不同 ID”解释为“没有语义近重复”。

## 15. 样本组装与一致性验证

### 15.1 build_dataset_record(...)

输入源语义、rules、生成元数据和 user_text，返回 DatasetRecordSpec：

```text
semantic_spec + rules
  → build_query → gold_query → build_constraint_signature
semantic_spec
  → count_hard_semantic_clauses
semantic_spec + rules
  → collect_normalization_rule_ids
以上结果 + 源元数据
  → make_sample_id
  → DatasetRecordSpec
```

schema_version 从 rules 获取；调用方不能另传 Gold、signature、count、规则 ID 或 sample_id 覆盖内部结果。
内部 collect_normalization_rule_ids 会再次 build_query；当前以复用验证为主，尚未做去重调用优化。

它不 strip user_text，也不从文本抽取语义。即使调用者传入与 spec 不一致的自然语言，
只要元数据形状合法，当前函数也不会自动发现。后续 controlled realization 和语义保持验证仍需实现。

### 15.2 validate_dataset_record(record, rules)

输入已存在记录和规则，成功返回 None，失败抛 ValueError：

1. 检查 record/rules 类型及 schema_version 相等。
2. 对保存的 Gold 做结构和领域校验。
3. 从 semantic_spec 重新 build_query。
4. canonicalize 保存 Gold 与期望 Gold 再比较。合法 key/set-like 顺序变化被忽略，文本列表顺序保留。
5. 用记录的源字段重新 build_dataset_record，顺便验证 metadata、seed、raw text 和可选改写字段。
6. constraint_count 另外要求非负 int 且非 bool，避免 True == 1 的 Python 比较陷阱。
7. 比较 signature、count、normalization IDs、sample ID；任意不一致直接报错。

不会修复或替换记录中的错误值。它保证内部一致性，不是数字签名、防篡改鉴权或自然语言语义裁判。
如果来源字段与所有派生字段一起被合法重建，它不会判断这些来源是否真实经过人工审核。

该管道已实现获取、规范化、hash、严格读取、bundle 写入、audit 校验、批准子集构建以及
DomainRules 联动。代码能力完成不等于正式审核完成；仓库中的 example audit 仍只是占位示例。

### 16.1 数据模型

| dataclass | 关键含义 |
|---|---|
| TaxonomyTagSpec | id/name/description/category 与 spoiler/adult；没有 media-specific rank |
| CanonicalTaxonomySnapshot | snapshot_schema_version、genres tuple、tags tuple |
| TaxonomySnapshotManifest | source/resource/fetched_at_utc、数量、canonical_sha256、快照结构版本 |
| TagAuditRecordSpec | tag 身份、approved、reason、aliases、标记与 source_snapshot_hash |
| ExecutableTagSpec | 批准后保留的 tag 身份、aliases 与标记 |
| ExecutableTagSubset | subset_version、derived_from_snapshot_hash、批准 tags |
| ExecutableTagSubsetManifest | subset_version/subset_hash/来源 hash/approved_tag_count |

模型定义不等于自动验证，应通过 builder/loader 使用。fetch 日期在 manifest，不参与 canonical 内容 hash。
schema_version、snapshot_schema_version、subset_version、dataset_version 分别标识不同契约。

### 16.2 已实现接口的职责

| 文件/函数 | 输入 → 输出与关键边界 |
|---|---|
| taxonomy_client.fetch_anilist_taxonomy | endpoint/timeout → 完整原始响应；不排序、不裁剪 |
| taxonomy_snapshot.build_canonical_taxonomy_snapshot | 原始响应 → 筛选字段和排序后的 snapshot；检查唯一 ID/name |
| canonical_taxonomy_to_mapping / dumps_canonical_taxonomy | snapshot → 固定形状 mapping / 稳定 Unicode JSON |
| load_canonical_taxonomy_snapshot | canonical 文件 → 已校验模型；不静默修复非 canonical 内容 |
| taxonomy_snapshot_sha256 | canonical UTF-8 JSON → SHA-256；不 hash HTTP bytes |
| build_taxonomy_snapshot_manifest | snapshot + 获取元数据 → 计算数量/哈希的 manifest |
| write_taxonomy_snapshot_bundle | source + output_dir/时间 → source/canonical/manifest 文件 |
| tag_subset.load_tag_audit | 人工 JSON → 审核 tuple；不补默认批准 |
| validate_tag_audit | audit + snapshot → 核对来源 hash、身份和 aliases 冲突 |
| build_executable_tag_subset | 已审核记录 + snapshot/version → 仅 `approved is True` 的子集 |
| executable subset 序列化/hash/loader | 子集 ↔ canonical JSON，并计算独立 SHA-256 |
| validate_domain_rule_tag_targets | subset + rules → group targets ⊆ active tags ⊆ approved subset |
| write_executable_subset_bundle | 子集 + output_dir → executable_tags/manifest 文件 |

两个 CLI 的 `main()` 都已经连接业务接口。`fetch_anilist_taxonomy.py` 生成 snapshot bundle；
`build_executable_tag_subset.py` 读取 snapshot/audit/rules，验证后生成 subset bundle。它们禁止覆盖
已有目标，但多文件写入不是事务，也没有自动重试或清理。示例 audit 的占位 ID、零 hash
不能当作真实人工批准结果。

## 17. 可运行的离线贯穿示例

从项目根目录启动 Python 后执行。示例使用当前空 soft 词表，因此模糊表达明确放入 unresolved。
无需 API、无需写数据文件；仅演示已经实现的 DatasetRecord 链。

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path.cwd() / "src"))

from anime_pref.schemas.preference_query import (
    SemanticSpec, SetConstraintSpec, RangeConstraintSpec,
)
from anime_pref.data.query_builder import load_domain_rules, dumps_query
from anime_pref.data.dataset_record_builder import (
    build_dataset_record, validate_dataset_record,
)

rules = load_domain_rules(Path("configs/domain_rules.v0.1.1.json"))
spec = SemanticSpec(
    genres=SetConstraintSpec(any_of=("Sci-Fi", "Mystery")),
    tag_groups=SetConstraintSpec(none_of=("HAREM",)),
    year=RangeConstraintSpec(min=2010),
    episodes=RangeConstraintSpec(max=24),
    formats=("TV",),
    status=("FINISHED",),
    reference_titles=("Steins;Gate",),
    unresolved_preferences=("节奏紧凑",),
)
record = build_dataset_record(
    semantic_spec=spec,
    rules=rules,
    dataset_version="learning-demo-v1",
    semantic_family="genre_harem_year_episode",
    generation_family="manual_demo",
    template_id="manual_001",
    seed=7,
    user_text="想看2010年及以后的科幻或悬疑TV动画，已完结、最多24集，不要后宫。参考Steins;Gate，希望节奏紧凑。",
)
validate_dataset_record(record, rules)
print(dumps_query(record.gold_query))
print(record.constraint_signature)
print(record.constraint_count)
print(record.normalization_rule_ids)
print(record.sample_id)

assert record.constraint_count == 6
assert record.normalization_rule_ids == ("HAREM_EXPANSION_V0_1_1",)
assert len(record.sample_id) == 71
```

预期 Gold（实际 dumps_query 为紧凑单行）：

```json
{
  "hard_constraints": {
    "genres": {"all_of": [], "any_of": ["Mystery", "Sci-Fi"], "none_of": []},
    "tags": {"all_of": [], "any_of": [], "none_of": ["Female Harem", "Male Harem", "Mixed Gender Harem"]},
    "year": {"min": 2010, "max": null},
    "episodes": {"min": null, "max": 24},
    "formats": ["TV"],
    "status": ["FINISHED"]
  },
  "reference_titles": ["Steins;Gate"],
  "soft_preferences": [],
  "unresolved_preferences": ["节奏紧凑"]
}
```

预期 signature：

```text
GENRE_ANY + TAG_NONE + YEAR_MIN + EPISODE_MAX + FORMAT + STATUS
```

count=6：genre OR、后宫排除概念、年份下界、集数上界、format OR、status OR 各一条。
reference 与 unresolved 不计数。示例是手工配对文本与 spec，当前程序并未自动证明两者的语义一致。

排查建议：

- import 失败：检查是否从项目根目录执行，或已配置 src 路径/editable 安装。
- 未知 soft：当前批准词表为空；检查理论批准与输入字段，不要让 builder 自动猜映射。
- 文件已存在：采集写入采用独占创建，选择新的输出目录；不要为重跑覆盖原始证据。
- taxonomy/audit identity 错误：核对 manifest 的 canonical hash、tag ID/name/category 和 flags。
- 控制台中文异常：区分终端编码与文件实际 UTF-8 内容；必要时用 python -X utf8 -B 运行，不能仅据显示就重写数据。
- bool 边界错误：Python 的 bool 是 int 子类，但项目数值契约明确排除它。

## 20. 当前边界与后续审查点

1. taxonomy/snapshot/subset 代码已实现，但仓库没有正式采集和人工审核产物；当前 builder 仍使用本地有限白名单，不能称为全量审计完成。
2. HAREM 的 all_of 已被配置禁止；未来若引入多个 OR 组并分别要求满足，需要明确扁平 any_of 是否足够表达。
3. soft 词表为空；扩展需批准映射。unresolved 表达也须符合 canonical 字符串规则。
4. 数值边界已加入，但只是有效性保护；没有确定 sampler 的分布范围，也没有检索缺失值策略。
5. 作品采集保留 rank；Query 仍没有 rank 阈值与执行器，不能自动推断强匹配。
6. 结构校验、领域校验、canonicalization 和 identity 各有边界，不能互相替代。
7. sample ID 包含来源和文本，不是语义去重 ID；signature 也不能替代按 generation family 防泄漏切分。
8. validate_dataset_record 保证内部一致性，不检查原始文本与 spec 是否语义对齐，不核实元数据来源真实性。
9. DomainRules 手工构造可能绕开 loader 检查，版本号未严格限定唯一支持值。
10. frozen 不等于嵌套容器完全不可变；多文件输出不是事务，也没有自动恢复。
11. 没有 semantic sampler、controlled realization、LLM paraphrase、split、训练或推荐执行。本次没有推进这些模块。
12. 已有测试全部通过不证明完整覆盖，尤其不证明真实网络可用或审核内容正确。

需新增语义政策时，应回理论分支确认相应契约，再更新实现与测试。
这里记录实际工程边界，不替理论分支决定新规则。
